# 首轮评审效果验证：pilot-v1

执行日期：2026-11-11。8 个开源 PR、13 次角色评审、4 次修复对照、2 次独立重跑，19 次均完成。停止于内部验收；没有修改评审器实现或提示词，没有接入 workbench。

这轮结果支持继续将四个 agent 用作建议型评审：首轮建议有代码依据，且发现了参考标签之外的问题。不过，召回不完整，工具链常识也可能产生错误建议。此次是小样本诊断，不能把结果外推为全场景准确率。

## 数据与执行条件

- 来源：[ReviewBench](https://github.com/review-bench/ReviewBench)，冻结 revision、PR base/head、标签取舍、运行代码/提示词 SHA256 见 [manifest](reviewbench-pilot.json)。保留 MIT 声明；各被评审仓库保留其自身许可证。
- 给评审器的输入仅为隔离仓库、base/head 和自身角色；没有业务需求、PR 描述、参考答案、评分依据或其它角色的结果。仓库自身的代码、测试和文档可读。
- `gpt-6.1-sol`、high、最多 30 轮、压缩阈值 120000；snapshot/workspace 工具集合。所有报告 actualModels 一致。本轮没有给评审器开启联网或数据库工具。
- 先根据代码核验并冻结 11 个“角色/问题”参考组，再运行评审。重复位置合并为同一根因。Sia 的流式错误参考以及 SDK 的推测性抽象参考不进入召回分母；仍检查它们的评审输出。
- 由当前执行代理逐条进行源代码判定，属于单一评估者判定，没有独立人工复核或自动 LLM 裁判。明确区分有依据、可选收益和反证；没有运行全部上游项目测试。
- 开发集 5 个 PR，首次留出集 3 个 PR（butlers、msgraph、torchfont）。本轮未调提示词。现在结果已经展开，后续若针对它们调优，就应补充新的未见留出集。

| 方向 | 完成次数 | 有依据的建议 / 输出 | 明确可行动 / 可选 | 参考命中 |
|---|---:|---:|---:|---:|
| quality | 4 | 7 / 7 | 6 / 1 | 2 / 3 |
| performance | 3 | 2 / 2 | 1 / 1 | 1 / 3 |
| simplify | 3 | 2 / 2 | 0 / 2 | 1 / 2 |
| comments | 3 | 4 / 4 | 4 / 0 | 3 / 3 |

参考命中为 63.6%。建议有效性和召回是两个不同维度：未匹配参考标签的新发现也可以有效，未输出错误建议也不代表没有漏报。15/15 只描述本轮首轮输出；修复对照另外出现了 1 条反证，不能宣称所有输出均正确。

开发集参考命中 4/6，首次留出集 3/5。单份报告没有同根因重复项；跨角色存在交集，例如 catalog 的重复请求同时被 quality 和 performance 提出，不应在汇总给调用方时算成两个独立问题。

有价值的新发现包括：AA 测试直接调用自身 mock、补丁未覆盖已导入别名；Sia 的总计接口只取前 1000 条；butlers 的 AsyncMock.acquire 不满足异步上下文管理器协议；wallet 在关闭 Debug 时仍计算编码参数。这些都按实际源代码核验，没有因不在精选参考中而判为误报。

四个未命中参考：

1. quality/catalog：新增额外仓库抓取的异常静默丢弃。评审发现了另一个真实的重复请求问题，但漏掉日志诊断问题。
2. simplify/butlers：跨文件重复的运行时配置工厂。评审提出了有效的单文件冗余工厂删除，但不同于冻结的共享工厂参考，不作宽松替代计分。
3. performance/wallet：字符串转字节再写日志的冗余转换。评审提出关闭 Debug 时跳过整个编码块，收益可能更广，但未直接指出这一转换根因，因此严格计为参考未命中。这是微优化，不代表漏掉严重回归。
4. performance/torchfont：首次读取单个 glyph 的 axes 会构建全部样式轴数据。报告 limitations 实际承认首次全量转换，但因未证明显著影响而没有形成建议。这里暴露的是建议阈值与潜在规模成本的取舍，不是完全没看见代码。

## 证据验证与一条被反驳的建议

- 从 catalog 原始与修复后的实际源码提取函数，以纯 mock 网络执行：前端和导出脚本每个额外模型请求均从 2 次降至 1 次，返回数据相同；错误日志从 0 条变为 1 条，返回数据相同。脚本：[check-pilot-controls.ts](../scripts/check-pilot-controls.ts)。这不是完整浏览器/API 集成测试。
- wallet 修复仅改两处日志字段构造，保留 ASCII hex 内容、顺序与截断规则；经静态检查和 gofmt 检查，没有做吞吐基准测试。
- msgraph 恢复说明由启动路径、缓存赋值与调用点核验；不存在进程内重试入口。
- msgraph 的 `.mcp.json` 建议由评估者额外核验[官方客户端文档](https://code.claude.com/docs/en/mcp#project-scope)。评审器本身没有联网，这个额外证据不能归功于评审器。
- 修复对照中的 comments 断言 `.gitignore` 会使 npm 分发包漏掉 `dist/loader.js` 等模块。使用真实 package.json/.gitignore、惰性占位构建文件、npm 11.20.0 / Node 26.13.0，执行 `npm pack --dry-run --ignore-scripts --json`，实际包含入口和这两个辅助模块。故将这条无条件断言标为 `unsupported_incorrect`。没有执行目标仓库脚本，也没有证明所有历史 npm 版本的 npx 行为；它至少需要提供具体失败版本/产物，不能仅凭忽略规则下结论。[可重复实验](../scripts/check-pilot-packaging.py)。[npm 文档](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#files)本身还包含入口文件的打包例外，因此不能只摘取 gitignore 规则推断完整包内容。

所有 25 条输出（含对照与重跑）均有判定：24 条有依据、1 条存在反证、0 条未决。重跑输出并非独立样本，不把这个比例当成扩展准确率。

## 成本、完整性与范围

首轮累计 2,347,851 tokens，19 次累计 3,015,261 tokens，包含各轮重复输入上下文，不等于单次上下文大小或独立阅读量。首轮各任务耗时之和 890.5 秒；任务并发执行，这不是墙钟总时长。发生 1 次压缩；无因轮数或错误而未完成的任务。未根据这些 token 数推算费用，因为没有拆分计费缓存和输入输出价格。

执行后核验所有冻结 src/prompts 哈希；8 个原始仓库仍处于指定 HEAD 且工作区干净。修复变体在独立克隆中，提交和补丁可重建。报告 `pass` 表示没有阻断级条目，可能仍带 advisory suggestion，不等于“没有问题”。

本轮测的是 CLI 的实际评审效果，不是调用方通过 skill 发起任务的端到端采用效果；也不是异常退出/续跑专项压力测试或数据库性能测试。已有工程测试与本轮效果测试分开解释。本轮收尾重跑 `bun run check`、`bun test`（12 通过、0 失败、76 个断言）和 `bun run build` 均通过；指标重算与两项定向实验也通过。

## 后续优化依据

优先补充证据要求：包管理器、编译器、框架默认行为等外部契约，要求固定版本依据或小型复现；证据不足时降级为待验证假设。这比扩大输出数量更能减少无效建议。

其次校准 performance 的建议阈值：区分已测量收益、确定的重复工作、首次全量构建的条件性风险；允许附规模前提的建议，避免把缺少基准一概等同于不值得报告。再考察 simplify 的跨文件重复识别，保持局部行为约束，避免引入泛化框架。

本轮没有实施这些提示词优化。下一轮应使用同一冻结集做回归，并新增第二来源（如 Martian / SWE-PRBench）的未见子集；对既有样本的分数提高不应算作新的泛化证据。
