# 第一轮收尾验收：Quality、Comments 与主控去重

验收围绕一个决定：只有当前变更引入了可定位、可说明后果的问题时，调用方才有依据阻断。Quality 核对受影响的实现与必要验证，Comments 核对读者按文档操作的后果。主控沿调用链确认根因和修复动作，保留每份证据。

## 内部验收通过

2026-11-18。最终构建上共 24 次独立回放：Quality 主集 12 次，Comments 主集 8 次，另用一对主控保留的提交交叉运行两个角色 4 次。全部实际返回 gpt-6.2-sol、high，未读 diff 均为零。三组累计分别为 4,233,007、1,429,609、47,421 个 provider 计数 token，合计 5,710,037；只统计最终组合，含重复上下文，不能换算为账单或单次上下文长度。

- Quality 保住故障持续拒收、硬配额、错误指南和归档丢数据四个必要阻断。修复目标均未复报，旧测试 ID 在原始与真实修复中均为建议。Catalog 两个修复对照分别消除了重复读取和静默漏导目标。其它相邻项的漏报见下文。[最终 12 份报告](quality/final.json)
- Comments 8 个样本中，5 个保留了预期阻断，3 个对照无阻断。实跑的每个外部事实均在三次查询内，未发现借别名重复查询。8 份报告均无禁用控制字符。早期 MCP 漏报、严重度偏差、跨站重复查询和文档建议遗漏实现交接均保留在[调词裁决](comments/adjudication.md)及[六轮原始记录](comments/reports.json)。
- 独立交叉样本最终 A 有四条原始阻断，按可观察后果和修复动作合并为两项。B 两个 reviewer 都无阻断。仅有一条迁移说明建议。[最终 4 份报告](independent/v4.json)
- 类型检查、四个入口的构建及 37 项自动化测试通过。CLI 校验解码后的报告文本；测试验证含裸 ESC 的建议被拒收并可重新生成，耗尽轮次可续跑。新 Comments 任务按产品与契约类别持久化三次查询额度，跨主机、压缩和进程中断延续。用户或模型使用产品别名时仍需要正确归组。旧任务保留创建时的工具接口。[CLI 行为](../../README.md)

## 怎样计分

每个角色与输入组合启动独立任务，使用固定 Git 提交和同一提交的干净工作树。角色指令、实际模型与构建摘要随报告记录。调用方另用真实函数和替身验证关键行为。退出 1 表示 reviewer 报告阻断；一个正确指出预设缺陷的样本可以通过评测。修复对照检查目标根因是否消失，并逐条核对其它发现。模型错误、未完成和校准未达标的早期报告保留。

| 验证集 | 检查内容 | 证据 |

## 可以复核的行为

- 登记表首次查询失败后，原实现把错误缓存为空名单；真实修复恢复下一次重查。旧事件 ID 的解析差异在 base 已存在。探针验证到身份检查和测试事件的写入，未做生产连接器端到端测试。
- 归档夹具给 65 条事件，第一批 50 条尚未写入就从源队列删除。故障后重试只找回 15 条，调整为成功后再删则归档全部 65 条。
- 旧接入指南的请求示例实测返回 400，修订后的示例返回 201。重试指南把五秒当成五毫秒时，实测再次返回 429，等待 5000 毫秒后返回 200。
- 在独立交叉样本中，零次重试实测发送三次，旧回执示例读出 undefined。修复后发送一次，示例得到正整数。两者需要独立修复，一处改代码，一处对齐示例；主控保留报告来源并分开验证。
- Catalog 的相邻发现并非全部稳定。最终三份 Catalog 报告中，保留旧自定义配置的升级问题得到两项建议、漏报一次。认证头的目的地仅在性能修复对照中被指出，另两次漏报。单次定向回放不提供总体准确率，修复对照只对已核查的根因成立。
