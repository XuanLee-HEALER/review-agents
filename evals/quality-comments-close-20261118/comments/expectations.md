# Comments 回放冻结标准

在修改 Comments 提示词和计分回放前冻结。每例新建独立 `review-comments` 任务，实际服务模型为 `gpt-6.2-sol`，effort 为 `high`，固定 SHA 与全 diff 覆盖匹配。使用原轮次和工具设置，工作目录为中性、干净的固定 head。以下新对照只用于评估。同一根因如需改代码或裁定产品规范，写入限制或交接，文档问题独立裁决。

| 样本 | 阻断与对照预期 |
| --- | --- |
| `guide-before` | 保留阻断。变更后只读 `delivery.channel`，未改的接入指南仍给顶层 `channel`，照例请求返回 400。定位指南中的文字和请求示例，保留仍正确的 201 和 `data.channel` 响应。 |
| `guide-revised` | 目标问题不复报且零阻断。同步示例返回 201。迁移或 400 说明可以建议，无兼容承诺或活跃调用方证据时不得要求兼容旧字段。 |
| `wording` | 零阻断。新增赘句可建议删除，零发现亦可。 |
| `mcp-original` | 保留项目配置文件名阻断。权威 Claude Code 项目配置要求根目录 `.mcp.json`，照原文 `mcp.json` 无法走该默认发现路径。克隆失败后需重启可提建议。 |
| `mcp-restart-doc` | 保留相同文件名阻断。补过的重启指引不重复报告。空索引与缓存为空的精确措辞可提建议。 |
| `comments-wellness` | 工具说明的 `rejected_non_primary_sender` 与新响应 `rejected_non_owner_sender` 不符，影响调用方状态分支，文档源是 `roster/health/modules/tools.py`。应保留这一独立阻断，不能把基线已存在的成功响应形状偏差捆成该阻断。查库错误永久缓存是独立实现缺陷，需交给实现评审。可针对本次新增的缓存或测试措辞提出文档建议。发送者空值分支在 base 已存在，缺乏本次变更新增的使用失败证据，不能直接阻断。多账号与规范冲突应明确待维护者确定的契约，不能借文档评审指定产品行为或撤权顺序。 |
| `retry-delay-wrong` | 新的纯文档变更新增错误重试教程。实际 `Retry-After` 是整数秒，`docs/exports.md` 新增文字和脚本把它当毫秒，按照说明等待后仍返回 429。应有一项阻断，修正文字并将示例换算为毫秒。列表默认条数偏差在同文件 base 已存在且同变更无关，不能附在阻断里。 |
| `retry-delay-correct` | 同一重试教程使用秒并换算毫秒，按教程等待后返回 200。重试根因不复报，零阻断。列表旧债是否提示不影响通过。 |

MCP 与 Butlers 的外部契约查询逐项回看实际工具调用。一次能够解释缺口的有效权威读取就可支持本地矛盾。同一事实最多尝试三个不同的外部读取、搜索或路径，含失败和重复；之后应基于已有证据裁决，缺少的证据写入 limitations。另记 CLI 自身的查询拒绝与模型主动停止，避免将请求被拒绝算作主动停止。所有有可复制建议的报告扫描控制字符，文本保留普通换行、回车和制表，ESC 及其它不允许的控制字符为失败。对正确的配置文件名、JSON 或 JS 修改再做内容级核验。
