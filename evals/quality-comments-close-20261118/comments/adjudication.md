| 轮次 | 影响裁决的结果 |

| 3 | 明确把旧错误带入新必走步骤仍受审，并禁止在阻断证据和替换文字里夹带无关基线问题。两例 MCP 都保住文件名阻断。原样本对 VS Code 配置访问 4 次，重启对照对 Copilot 设置访问 4 次，均违反逐事实三次上限。Butlers 单列缓存失败的实现交接，并将基线成功响应移出阻断。 |
| 4 | 限于足以改变裁决的外部事实，使用权威窄页，先看命中内容再改查替代来源。同一事实最多三次已满足，两例 MCP 只阻断文件名。Butlers 仅阻断工具状态，额外测试和缓存措辞为建议。仍把首次查询异常造成后续持续失败只写在注释建议中，没有按冻结标准在 limitations 单列实现交接。 |
