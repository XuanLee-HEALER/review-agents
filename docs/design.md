# Independent review runtime

Four advisory roles share one bounded Bun/TypeScript loop. Role prompts are project-owned; external source and documentation never supply behavioral authority. There is no business requirement input, code mutation or workbench dependency in the runtime. New roles use an explicit CLI entrypoint and prompt; tools are selected from static sets at task creation.

A task directory contains an atomically replaced state.json and unique live-process claim files. State includes saved model/effort, original cwd, pinned commits, instructions, transcript, diff coverage, limits, accounting, last error and terminal report. A complete model/tool round and successful compaction are checkpoints. Failed requests or interrupted read-only tools can be repeated. Completed results are replayed without a new model call. Caller decides whether mutable surrounding context still justifies resuming; runtime does not inspect workspace drift. Claims are local-host process locks, not distributed coordination.

Snapshot tools read Git objects and require full non-excluded diff pagination. Instruction files are excluded explicitly. Workspace tools inspect uncommitted and sibling context under original cwd using a restricted command launcher and macOS sandbox. System/runtime reads are exceptions needed to execute installed binaries; this is not a hostile-code isolation product. Web GET and PostgreSQL/usql SELECT are separate optional sets. All external text remains untrusted evidence. No arbitrary shell, project test execution or automatic code editing is exposed.

Reports distinguish pass, findings, incomplete and error; findings require a changed path and valid source line. Coverage demonstrates reads, not understanding. Limits, excluded files and tool failures remain visible. New-task defaults are gpt-6.2-sol, medium effort, 30 total rounds and 120000 approximate tokens before compaction (at most three compactions). Effort controls review Responses requests; SDK compaction accepts a model but no reasoning-effort setting. Model choices are exactly gpt-6.2-astra and gpt-6.2-sol (6.2 series), and gpt-6.1-terra (6.1 series); effort choices are medium/high. Resume preserves saved values, defaults legacy missing effort to high and rejects explicit mismatches; switching model or effort requires a new task. Token accounting includes committed API responses and reported compaction usage; interrupted requests may incur unrecorded costs.

Integration tests execute CLI subprocesses with real Git fixtures and a local simulated Responses endpoint, exercise failure/recovery and sandbox boundaries, and do not require external credentials. Live self-review creates an isolated Git snapshot of this project and records each role independently; findings are verified by the owner. Workbench adoption is authorized and recorded in workbench-adoption.md; the runtime remains independent.

## Credit-balance classification

The runtime does not modify reviewed files or orchestrate fallback agents. Only a real SDK APIError with HTTP 429 and exact code `credit_balance_exhausted` produces exit 2, status:error and top-level errorCode:credit_balance_exhausted. A caller must check all three, not messages, generic 429 or the broader insufficient_quota type. Spend/usage limits, authentication, timeouts and incomplete states do not qualify. Source: [OpenAI error codes](https://developers.openai.com/api/docs/guides/error-codes), checked 2026-11-11.

Host workbench rules authorize a separate historical mutating-subagent fallback only for simplify/comments and own its scope, delegation and verification policy. Runtime skills describe the handoff without granting non-workbench callers editing authority. Quality/performance retain failure without this fallback; fallback delivery is never a CLI pass.
