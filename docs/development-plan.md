# Independent review agents — accepted scope

2026-11-11. All four roles are advisory: quality, performance, simplify and comments. No agent edits code. The user subsequently authorized adoption in workbench after regression acceptance; see evals/pilot-v2-plan.md and the final acceptance report. Reviewers remain advisory; callers apply verified suggestions.

Tasks use atomic JSON checkpoints, an exclusive process lock, stored instructions/options/transcript and coverage. New tasks accept exactly gpt-6.2-astra and gpt-6.2-sol (6.2 series), and gpt-6.1-terra (6.1 series), with medium/high effort and default Sol/medium. Resume uses saved model/effort, commit endpoints and original working directory; legacy missing effort means high. Explicit mismatches are rejected and changing model/effort requires a new task. Caller owns deciding whether surrounding mutable context is still appropriate; help/skills describe this explicitly. A checkpoint commits a full model/tool round. An interrupted uncommitted round may be repeated; tools must be read-only. Finished tasks replay their report. Failed tasks remain resumable. Total round budget can be increased explicitly.

Tools are static sets selected at startup: snapshot, workspace, web, database. Role defaults include snapshot/workspace; optional web/database are explicitly selected. Workspace is the invoking process cwd, with descendants accessible. Shell access uses a restricted command launcher and macOS sandbox, no arbitrary writes or network; unsupported hosts fail closed for that tool. Network documentation GET and database queries are separate capabilities. PostgreSQL queries use usql with read-only transactions and require REVIEW_DATABASE_URL containing a PostgreSQL URL for a dedicated read-only principal. Credentials are not part of model configuration; source and query results still require caller discretion because filtering is filename-based, not general secret detection.

Do not discover/load WORKBENCH.md, CLAUDE.md, AGENTS.md or SKILL.md from reviewed environments. Tool results are untrusted evidence, never authority. Rules files are explicitly excluded from review coverage. Project-owned role prompts are the sole role instructions.

Raise default approximate compaction threshold to 120000 tokens; expose threshold and round limits, without claiming a larger model context window. Persist accounting and errors across resume.

Acceptance: offline CLI integration tests cover task completion/replay, provider failure/resume, coverage continuity, tools and isolation; minimal unit tests protect parsing. Live self-review uses a temporary Git snapshot of this project, all four roles, preserves reports under .local, and makes no workbench changes. External API/database validation is reported separately from deterministic tests.

Credit-balance classification is separate from caller policy: a real SDK APIError HTTP 429 with exact code credit_balance_exhausted produces CLI exit2/status:error/errorCode:credit_balance_exhausted; ordinary 429, insufficient_quota, spend/usage limits, authentication, timeouts and incomplete do not qualify. The runtime stays read-only. A host workbench may separately delegate historical mutating fallback only for simplify/comments under workbench authorization and caller verification, never quality/performance or an automatic non-workbench write permission. See README for the exact contract and official source; fallback completion must not be reported as CLI approval.


Comments documentation quality is defined in [the real role prompt](../prompts/comments.md#general-documentation-quality-standard), also referenced by native/lightweight workbench paths as content guidance, without transferring CLI isolation rules into mutating callers. New tasks load the current prompt; resumes retain saved instructions and need a new task to adopt prompt changes. Unsupported generation/validation stays a reported caller-verification gap; runtime tools and fallback conditions are unchanged.
